# Changelog

## Unreleased

- `council`: new skill, adapted from Theo Browne's tstack council. Judges any subject, not only code: an idea, a plan, game mechanics, a UI in the running app. It seats one model per provider (by default Claude Opus and Codex GPT Astra), writes the evidence to files (the full plan, screenshots per width and state, a mechanic's numbers), and briefs every member identically and read-only. Each issue is adopted, declined with a reason, or taken to the user; the subject is revised and reconvened until every member says ship, for at most three rounds.
- `spec-review`, `spec-consolidate`: `spec-review` now only reviews. It writes its findings to a file (each with its sites, the move, what it deletes and how it was verified) and leaves the repository as it found it. The new `spec-consolidate` takes one or more of those files, merges the findings they share, verifies each against the code, applies the confirmed ones, and publishes the PR, ending with a disposition table of every finding in every file. Several reviewers can now read one range side by side.
- `quality-control`: the review step runs a Claude Opus and a Codex GPT Astra `spec-review` side by side on the same brief, then an Opus consolidator on both files, and the report gives each finder's dispositions so the two models can be compared.
- `tackle-issue`: the defects review runs two reviewers side by side on the same brief, Claude Opus and Codex GPT Astra (reasoning effort `high`), and the report lists each one's findings under its model's name, marked fixed, declined, or found by both, to compare the two. The host must be able to start both, so plain Claude Code now stops at setup like plain Codex; T3 Code runs it from either.
- `babysit-pr`: new skill, replacing the `babysit` dependency. A pass reads the PR, verifies each finding against the code, fixes what is real and within the PR's purpose, declines the rest with a reason, pushes once, and answers and resolves each thread. It waits on the host's PR watcher instead of polling every 30 to 60 seconds, makes one pass when an orchestrator watches the PR, and reports instead of waiting when only a person can move the PR on. `tackle-issue` and `quality-control` use it.
- `tackle-issue`: a review finding is fixed when it is real and within the issue, with the smallest change that removes it; the rest is declined with a reason and listed as a follow-up. Every P2 used to be fixed, which grew PRs one small fix at a time.
- `tackle-spec`: one auditor checks every open ticket, and the tickets against each other; a spec over about six tickets gets two. One per ticket cost 10 to 16% of a run's subagent spend, each rereading the parent and the repository's guidance, and saw the other tickets only as a paragraph in its brief.
- `tackle-spec`, `quality-control`: a brief carries what the skill cannot know and leaves the skill's steps to the skill. A kickoff that summarised `tackle-issue` as build, publish and follow up led an implementer to skip the review the summary left out. Roles name a model family, and the orchestrator takes the newest one `orchestrator_capabilities` lists unless the user or the project's `AGENTS.md` names another.
- `blast-it`: writes the PR body itself, without the `pr` skill: the problem, the change, then only what the diff cannot show (Deviations, a line of proof, what reverting would not undo, and what the brief asks for). Bodies had been running to 600 to 1,500 words.
- `test-plan`: a plan has a depth. Smoke, the default, is about 20 cases in one lane: an observe case per open question, each feature's main path, the seams between changes, and the refusals that guard something hard to undo, with the areas left to the automated tests named. Thorough, on request, is the full plan as before: every requirement mapped to a case. `quality-control` plans at smoke depth unless the user asked for thorough testing. Across four spec runs, 307 thorough cases led to two fixes, one of them from rerunning the automated baseline, and the planner was the most expensive subagent of each run.
- `tackle-issue`: one review round before publication replaces the local review plus the review of the published PR after it. `code-review`'s Standards and Spec subagents and a defects reviewer, briefed from the new `defect-review.md`, start together on the committed change; findings are fixed before the PR opens and nothing is posted to it. The defects reviewer is a Claude Opus subagent. The flow no longer needs a temporary clone or a fix-and-push cycle after publishing.
- `tackle-issue`: the simplify and prune steps follow the skill's own brief. `tdd`, `codebase-design`, `prune-tests` and `simplify` are no longer dependencies: in 41 runs the first two were never opened, and the last two were mostly applied from the skill's summary without opening them.
- `tackle-issue`: between steps only the affected tests and the typecheck run. The full verification runs once, on the head being published after the default branch is merged into it, and again only when a later push changes that head. It used to run after pruning and again after every review fix, three to six full runs per ticket.
- `quality-control`, `tackle-spec`: the orchestrator decides a product question with a clear route itself (it follows from the spec, a recorded decision or the code's existing pattern, and keeps the agreed scope), records it like an answer, and lists it in the final report as its own; only forks (scope added or dropped, a recorded decision reversed, options that each have a fair case) go to the user. A ticket starts once it is ready and its own red flags are settled, without waiting on other tickets' forks.
- `quality-control`: **Settled** takes the automated review's one pass on the PR; the orchestrator requests no second review and reads commits pushed after it itself. A PR whose head lacks the default branch goes back to its subagent to merge it and reverify before merging, since GitHub's mergeable flag does not say the combined code builds.
- `tackle-spec`: the orchestrator reads only titles and blocking edges when building the graph; ticket bodies are the auditors' to read.
- `quality-control`, `tackle-spec`: a subagent makes one `babysit` pass and hands back with checks still running; the orchestrator watches the PR until settled. `tackle-issue` gains the delegated mode this relies on, and waits on its own long commands with the harness's own background wait. A handback that says it is waiting on its own background command is left to resume by itself rather than nudged.
- `quality-control`, `tackle-spec`: questions go to the user in a message rather than a blocking question tool while any subagent runs, so settled PRs keep merging. Every brief tells a subagent to stop any dev server it started and release any slot it took.
- `tackle-spec`: every ticket is audited at once before the first starts, and all product questions go to the user in one round; a ready ticket is re-checked only when a merged PR it builds on lists Deviations that touch it. One PR per ticket, split only when the user will read it by hand (then stacked). Tickets that each generate a numbered file, such as a migration, run one after the other.
- `quality-control`: a plan over about 60 cases runs as up to three lanes, one tester and one slot each, released when the lane is done, when the repository can run local slots side by side (a `use-slot` skill). Defect FAILs go to the fixer at once; the user's change decisions follow to the same fixer and PR.
- `test-plan`: observe cases only for departures a user can see in the running app; the baseline cites CI's run on the pinned commit instead of rerunning it; expected results follow the state earlier cases leave; a gesture whose timing the device tool cannot hold goes to a real-device check. The restore checklist is gone: a run restores no data, with every created record prefixed `QA `, and ends by tearing down its disposable environment, such as releasing its slot; in a shared one the tester puts back the settings its cases changed. A large plan is split into self-contained lanes, one slot each, when the repository has slots.
- `execute-test-plan`: a gesture whose timing the device tool cannot hold is BLOCKED, not a FAIL. It restores no data: it tears down a disposable environment, such as releasing its slot, once the report is saved, and in a shared one puts back the settings its cases changed. A lane brief takes that lane's slot and runs only that lane, and the Playwright fallback also covers a browser tool that fails on its first three tries.
- `tackle-spec`: the audit checks each ticket for red flags (product questions, premises the code contradicts, names later tickets rely on) instead of tightening every detail; settled flags become the ticket's binding Decisions, and the rest of the ticket is a plan the implementer may depart from, listing why under Deviations.
- `tackle-spec`: new user-invoked skill for T3 Code. Delivers a spec issue end to end: reads its sub-issues as a blocking graph, tightens each ticket against the current default branch with product questions to the user, tackles it with `tackle-issue` in a subagent (up to two at once), merges each PR once settled, then runs `quality-control` over the spec. Leaves the parent open for the user. An issue with no sub-issues runs as a spec of one ticket, for a big ticket that earns the full pass.
- `spec-review`: new user-invoked skill. Consolidates a spec's merged tickets after agents built them independently: an inventory of everything the range adds with its siblings, judo moves that collapse duplicated code, harmonisation with the codebase, then seams, coverage and drift. Ships one behaviour-preserving PR with open questions for anything that would change behaviour. Replaces `thermo-nuclear-code-quality-review` as `quality-control`'s review step.
- `quality-control`: runs at spec level once a spec's tickets merge. Briefs carry the scope's recorded decisions as binding and route open questions and observations to the user in one round before the fix PR; Decide sorts each FAIL into a fix, a plan correction or a product question. Briefs name skills by their installed absolute path, the tester runs in the checkout the plan names, merges use the repository's own merge method, and an unfinished handback resumes the same subagent.
- `execute-test-plan`: uses the browser the environment provides, with Playwright as a disclosed fallback. Adds the OBSERVED result for observe cases and the evidence rules a built-in browser needs (saved PNG files, measured widths, fresh snapshots).
- `test-plan`: adds observe cases for open questions and departures the work already records, fixes the screenshot marker as 📸, adds OBSERVED to the report template, and asks for a baseline that runs the tests rather than replaying a cache.
- `quality-control`: new user-invoked skill for T3 Code. Orchestrates a thermo-nuclear review and fix PR, a test plan, a headless browser test run, and a fix PR for failures; subagents own and babysit their PRs, and the orchestrator merges each once settled.
- `execute-test-plan`: new skill. Runs a written test plan in a headless Playwright browser with screenshot evidence, restores test data, and removes its Playwright install when done.
- `tackle-issue`: pass earlier review context to Claude, record narrow mechanical skips, and keep optional nits out of release gates. Required review failures still block completion.

## 0.1.0 — 2026-10-13

Initial public collection of five skills previously maintained as personal global skills.

- Added human-facing documentation, synthetic examples, dependency installation, and license/attribution files.
- `blast-it`: reuse existing commits, resolve open PRs explicitly, and distinguish missing PRs from API failures.
- `prune-tests`: support audit-only requests and require evidence before discarding regression or boundary coverage.
- `tackle-issue`: check dependencies early, prune and commit before local review, and report human/infrastructure blockers rather than polling indefinitely.
- `test-plan`: distinguish planning from execution, keep credentials and personal data out of artifacts, and make shared publication opt-in.

The unused `trim-agent-context` skill is not part of this collection.
